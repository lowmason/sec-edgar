### F1 — Important: current completion can omit a formerly affected output quarter

**Plan locations:** `specs/plans/4-sec-filing-index-ingestion-stage-4-spec.md:990`, especially `:1008`–`:1015`; the resulting omission affects `pending()` at `:448`–`:454` and runner selection at `:1141`–`:1154`.

This is reachable with nonempty supported inputs, without a hypothetical zero-row source. A quarterly source for 2026Q3 initially contributes a Q3 row; its newer retained snapshot moves that row into Q4. The current publisher can publish Q4 while refusing Q3 because the replacement quarterly source has no target-quarter membership. A later daily run can drop the unresolved source from the queue and claim `no_new_sources`, although Q3 remains unresolved. A daily source whose old quarter suffers a publication conflict produces the same omission.

**Required correction:** derive current completion from every affected quarter under the existing publication rules, including prior source membership, and retain failed/gated/partially published units until all of those obligations are resolved. Do not reduce this to a `Processing.published` flag. Keep exact processing-version/source/snapshot checks and validated immutable observation/manifest evidence.

**Authority and decision status:** this restores `specs/sec-filing-index-ingestion-stage-4-spec.md:57`, `:61`, `:65`, and `:69`, and Plan 4's explicit all-affected-quarters instruction at `:585`. It is an example-code defect, not a request to change coverage policy. Record the correction before Task 2; no policy waiver is needed.

**Minimum regression:** seed the exact old/new quarterly case above with real raw bindings and publication commands; assert Q4 remains readable, Q3 remains refused, `current_complete` is false, and a subsequent daily run with valid empty listings retains a nonzero unresolved result. ### F2 — Important: retained retry-prefix quarantine is mistaken for whole-source quarantine

**Plan locations:** `specs/plans/4-sec-filing-index-ingestion-stage-4-spec.md:565` and `:573`, conflicting with the member invariant at `:195`–`:196`.

The planned adapter sets `MemberResult.quarantined = bool(collected.quarantined)`. That existing child counter is not a terminal source-state counter: collection retains bodies from unsuccessful transport attempts even if a later request succeeds. The existing regression source is explicit at `packages/sec-edgar-ingest/tests/test_collection.py:323`–`:329`: truncated prefix followed by a valid body yields `outcome == 'success'` and `quarantined == 1`. Production behavior follows from `packages/sec-edgar-ingest/src/sec_edgar_ingest/collection.py:226`–`:253`, `:334`–`:335`, and `:367`–`:386`.

A normal successful retry therefore continues through transform and publish, then the planned `MemberResult` constructor rejects it because both `transformed` and `quarantined` are true. Retained partial transport bytes also must not inflate the workflow's `quarantined_sources`, which the spec defines as a failed-source subset.

**Required correction:** derive the workflow whole-source quarantine status from terminal source refusal and exact child failures, while retaining transport-prefix quarantine evidence through the original child result/request receipts. Keep the member invariant; do not weaken it to permit accepted whole-source quarantine. Acquisition retry evidence and source refusal are distinct facts even though the existing child result uses the same word for its counter.

**Authority and decision status:** `specs/sec-filing-index-ingestion-stage-4-spec.md:12`, `:32`, and `:67` already decide the semantics. This is an integration mismatch with the shipped child interface, resolvable in Task 3 and its tests without changing accepted quarantine policy.

**Minimum regression:** run a real workflow using a fixture response sequence with one retained truncated/failed prefix and one valid full body. Require successful source completion, `quarantined_sources == 0`, exact retained prefix body/error/request evidence, unchanged five-attempt accounting, and readable published output. Retain the separate conflicting-duplicate test proving actual whole-source refusal still has no accepted observations or publication from that source.

### F3 — Important: a fresh workflow can skip an outstanding post-CAS repair

**Plan locations:** `specs/plans/4-sec-filing-index-ingestion-stage-4-spec.md:990`–`:1015`, `:448`–`:454`, and `:1141`–`:1154`; contrast `:587` and `:1208`.

After `PublicationRepairPending`, the pointer can validly contain the exact observation while ancillary repair and the child result remain unfinished. This is not an inference merely from a pointer: `packages/sec-edgar-ingest/src/sec_edgar_ingest/etl/publication.py:110`–`:120` commits the pointer before repair; `packages/sec-edgar-ingest/src/sec_edgar_ingest/etl/commands.py:253`–`:254` raises before creating a command result; and the existing regression at `packages/sec-edgar-ingest/tests/test_etl_cli.py:453`–`:495` asserts committed pointers, `result_ref is None`, unfinished Attempt, then successful exact repair with no further pointer advance. `capture_quarter` only validates pointer/manifest/data; it does not perform the repair (`packages/sec-edgar-ingest/src/sec_edgar_ingest/etl/reader.py:37`–`:47`).

Exact retry of the same workflow selection can reach the saved child and repair correctly. A *new* workflow, however, runs `pending()` and `current_complete` before selecting jobs. The helper can declare all committed quarters complete without examining the unfinished publish obligation or doing any repair. With valid empty listings, the new workflow can then report `no_new_sources` while the recorded child repair remains outstanding. The planned tests primarily cover exact invocation replay, leaving this cross-run shortcut uncovered.

**Required correction:** distinguish committed data authority from unfinished command/repair obligations when deriving the pending queue. A known unfinished publish must be repaired through the existing command boundary, or remain explicitly pending; current pointer membership alone cannot silently erase it. The original exact invocation remains resumable when its deadline permits; after expiration a new valid attempt may re-run the existing no-op publish/repair path. Do not add another publication authority or rewrite the old failed/unfinished result.

**Authority and decision status:** the explicit contract is `specs/sec-filing-index-ingestion-stage-4-spec.md:61`: neither workflow result nor member completion is finalized until child repair completes. Plan `:732` also says uncertain legacy publication is rechecked through ETL. This correction follows the approved contract; it does not require deciding whether a committed pointer is real publication—the pointer remains authoritative throughout.

**Minimum regression:** inject an ordinary ancillary repair error after a real CAS, verify no workflow result/member-complete receipt and no child result, then invoke a fresh workflow run with unchanged/empty listings. It must either complete the existing repair through a checked command or retain explicit unresolved repair. Require no extra pointer advance and no success/no-new report while repair remains outstanding. Cover exact retry separately, including the expired-original/new-valid-attempt boundary.
