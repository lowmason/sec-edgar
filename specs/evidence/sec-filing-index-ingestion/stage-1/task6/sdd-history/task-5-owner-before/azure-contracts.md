## Start, async, execution and durable-result decision table

`turnOffAsync=true` is the selected design choice for the single start Web activity: expose initial acceptance so the application owns bounded observation rather than ADF's default unbounded-for-this-policy follow-up. Activity `retry=0`; explicit response timeout at most 10 minutes, default 1 minute unless separately chosen later. Default `turnOffAsync=false` automatically GETs Location and can wait up to seven days; it does not prove exact execution correlation, is not the selected polling mechanism, and cannot turn ARM acceptance into worker success. ADF Web requires JSON object responses and supports at most 4 MB output; 202/no-body, Location header exposure and final response shape remain Stage 7. If output does not expose sufficient data, operator recovery is required before any additional launch; no latest execution fallback. [ADF Web](https://learn.microsoft.com/en-us/azure/data-factory/control-flow-web-activity).

Microsoft recommends at least one native retry for long-running replicas interrupted by maintenance. Accepted parent policy stays zero native retries because orchestration must distinguish confirmed failures from ambiguous launches and centrally limit replay; durable source worksets preserve resumable progress. This is a trade-off: a maintenance-interrupted replica can leave work incomplete, and zero retries is no maintenance guarantee. This disclosure requires review with the finding, not a redundant acceptance gate for the already accepted default; Stage 7 must retain maintenance/failure recovery and one-replay evidence. The recommendation and policy coexist without silently revising either. [Maintenance guidance](https://learn.microsoft.com/en-us/azure/container-apps/jobs).
