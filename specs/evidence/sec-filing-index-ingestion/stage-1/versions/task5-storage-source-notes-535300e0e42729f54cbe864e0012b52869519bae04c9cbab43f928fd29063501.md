## API and storage selections supported by retrieved documentation

- Select a Standard general-purpose v2 account (`kind=StorageV2`, `sku=Standard_ZRS`), HNS enabled, Hot default tier. The account-create table explicitly permits HNS with Standard_ZRS; the account-overview workload table explicitly shows Standard GPv2 + HNS + Hot + ZRS for analytics. This is a supported configuration; no account was provisioned or interrogated.
- Standard GPv2 supports Tables as an account service. The retrieved overview describes the account as containing blobs, files, queues, and tables and gives the Table endpoint. Combined with its HNS analytics configuration, this supports coexistence as a documentation inference. An explicit sentence that HNS does not disable Tables was not retrieved. Do not claim runtime coexistence was tested.
- For each application-owned raw/manifest/lock object, use only Blob APIs throughout that object's lifetime: create/upload/overwrite with Put Blob or Put Block + Put Block List, Get Blob, properties/metadata, and conditional Delete Blob. Do not introduce DFS Path Create/append/flush, NFS, or SFTP writes to those same objects. HNS alone does not prohibit block blobs. The known-issues page says DFS-created objects cannot be overwritten with PutBlock/PutBlockList, although PutBlob can overwrite within its API-version size limit. A later block upload is therefore unsafe if any tool first creates that object through DFS. Delete Blob cannot recursively remove directories; list results can include directories and delimiter support is `/` only.
- Put Block List updates overwrite properties/metadata, maintain an existing lease, and permit conditional requests. Its active lease ID must be supplied. Uncommitted blocks are collected after a week without successful Put Block/Put Block List calls; a Put Blob also collects them. Operational code should explicitly handle failed uploads and should not assume staged blocks are permanent.
- Use finite Blob leases for mutual exclusion, renewing before expiry. Documentation supports 15–60 seconds or infinite leases. An active lease enforces exclusive writes/deletes to that blob and requires the lease ID on PutBlob, PutBlock, PutBlockList, and DeleteBlob; missing IDs fail with 412. A separate lock blob does not automatically protect any Table entity or other blob. Lease-lost workers must stop protected work; application fencing and conditional updates remain required.
- For Table state compare-and-swap, send the exact retrieved ETag in If-Match on Update Entity. Changed ETags yield 412; reread/reconcile rather than unconditional retry. `If-Match: *` disables concurrency protection; omitting If-Match can invoke upsert for API versions 2011-08-18 and later. Do not substitute unconditional upsert for CAS.

## Network and logs

Jobs share environment networking/logging. Default managed networking accesses internet endpoints. Workload-profile environments support UDR/NAT Gateway egress and private endpoints, while legacy Consumption-only environments do not support custom egress/NAT. Outbound public IPs may change; do not promise stable egress IP without appropriate custom networking. Storage HNS private-endpoint guidance calls for both blob and dfs endpoints, because some operations redirect or require dfs, even if application writes use Blob only. Configuration and access were not tested.
