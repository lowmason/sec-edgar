## Limits and trust boundaries

1. Starting a job permits arbitrary execution-template overrides using the secrets and container-available identities. Excluding listSecrets does not contain this authority. ADF start MI and deployment operator must be trusted at worker/pull privilege level. Avoid built-in Jobs Operator/Contributor wildcard action sets.
2. Blob read+write custom role deliberately omits delete/move/add and management container creation. Blob write authorizes more than leases. Provision containers separately; if DFS ACL/move/append or container lease is later selected, this matrix requires re-review. This collection verifies Blob lease, not Lease Container.
3. Table entity update permission does not enforce CAS, allowed pointer content, partition/row scope, approval hash or separation of duties. Table-scoped RBAC permits all entities in that table. Container scope likewise permits contained blobs; use separate tables/containers or separately verified Blob ABAC conditions where stronger isolation is required.
4. RBAC-only AcrPull grants registry-wide image pull. Dedicated single-purpose registry contains that scope. ABAC mode could instead use Repository Reader (metadata/read and content/read DataActions) with a repository condition; catalog list is unnecessary. Mode selection is pending owner acceptance.
5. General ACR guide recommends disabling ARM-token acceptance, but Container Apps MI pull guide requires it enabled. Preserve enabled for this integration pending real pull proof. Neither successful Entra authentication nor assigned role proves pull success.
6. Contributor has no DataActions but can obtain storage keys and alter identity-bearing jobs. Its broad management powers must not be presented as inability to access data. RG RBAC Administrator also permits privilege grants unless constrained. A least-privilege custom deployment role requires finalized resource operations and must be authored/verified later; no such role was invented here.
7. RBAC Administrator cannot create custom role definitions. Custom role bootstrap needs a separate authority including Microsoft.Authorization/roleDefinitions/write at permitted assignable scopes; existing Owner/User Access Administrator can be broader authority. Exact bootstrap principal is unresolved.
8. Generic Microsoft.App async actions are catalog candidates only; grant only actions matching selected/observed Location route. Subscription scope is a proposed conservative assignment for location APIs; actual authorization and narrower scope feasibility are Stage 7 obligations. No 200/202 response or effective authorization was observed here.
9. Managed identity does not bypass DNS/TLS, public endpoint routing, firewall, network controls, quotas or policy. Identity endpoints and telemetry egress are sibling network-contract topics; public docs do not prove current tenant reachability.
