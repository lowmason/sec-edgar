L39: This article provides information about the schedule trigger and the steps to create, start, and monitor a schedule trigger. For other types of triggers, see cite9†Pipeline execution and triggers .
L40: When you create a schedule trigger, you specify a schedule like a start date, recurrence, or end date for the trigger and associate it with a pipeline. Pipelines and triggers have a many-to-many relationship. Multiple triggers can kick off a single pipeline. A single trigger can kick off multiple pipelines.
L41: 
L42: The following sections provide steps to create a schedule trigger in different ways.

L73:     3. Specify the time zone in which the trigger is created. The time zone setting applies to Start Date, End Date, and Schedule Execution Times in Advanced recurrence options. L74: (Ensure that the start date is at least 1 minute less than the execution time or else it triggers the pipeline in the next recurrence.)
L75: Note
L76: 
L77: For time zones that observe daylight saving, trigger time auto-adjusts for the twice-a-year change, if the recurrence is set to Days or above. To opt out of the daylight saving change, select a time zone that doesn't observe daylight saving, for instance, UTC.
L78: 
L79: Daylight saving adjustment only happens for a trigger with the recurrence set to Days or above. If the trigger is set to Hours or Minutes frequency, it continues to fire at regular intervals.
L80:     4. Specify Recurrence for the trigger. Select one of the values from the dropdown list (Every minute, Hourly, Daily, Weekly, or Monthly). Enter the multiplier in the text box. For example, if you want the trigger to run once for every 15 minutes, you select Every Minute and enter 15 in the text box.

L122: ## Azure PowerShell
L123: 
L124: Note
L125: 
L126: We recommend that you use the Azure Az PowerShell module to interact with Azure. To get started, see cite31†Install Azure PowerShell . To learn how to migrate to the Az PowerShell module, see cite32†Migrate Azure PowerShell from AzureRM to Az .
L127: This section shows you how to use Azure PowerShell to create, start, and monitor a schedule trigger. To see this sample working, first go through cite33†Quickstart: Create a data factory by using Azure PowerShell . Then, add the following code to the main method, which creates and starts a schedule trigger that runs every 15 minutes. The trigger is associated with a pipeline named `Adfv2QuickStartPipeline` that you create as part of the quickstart.
L128: ### Prerequisites
L129: 
L130:   * Azure subscription. If you don't have an Azure subscription, cite34†create a free account†azure.microsoft.com before you begin.
L131:   * Azure PowerShell. Follow the instructions in cite31†Install Azure PowerShell on Windows with PowerShellGet .
L132: ### Sample code
L133: 
L134:   1. Create a JSON file named MyTrigger.json in the *C:\ADFv2QuickStartPSH* folder with the following content:
L135: 
L136: Important
L137: Before you save the JSON file, set the value of the `startTime` element to the current UTC time. Set the value of the `endTime` element to one hour past the current UTC time.
L138: 
L139:     `{
L140:         "properties": {
L141:             "name": "MyTrigger",
L142:             "type": "ScheduleTrigger",
L143:             "typeProperties": {
L144:                 "recurrence": {
L145:                     "frequency": "Minute",
L146:                     "interval": 15,
L147:                     "startTime": "2017-12-08T00:00:00Z",
L148:                     "endTime": "2017-12-08T01:00:00Z",
L149:                     "timeZone": "UTC"
L150:                 }
L151:             },
L152:             "pipelines": [{
L153:                     "pipelineReference": {
L154:                         "type": "PipelineReference",
L155:                         "referenceName": "Adfv2QuickStartPipeline"
L156:                     },
L157:                     "parameters": {
L158:                         "inputPath": "adftutorial/input",
L159:                         "outputPath": "adftutorial/output"
L160:                     }
L161:                 }
L162:             ]
L163:         }
L164:     }
L165:     `
L166: In the JSON snippet:
L167: 
L168:      * The `type` element of the trigger is set to `ScheduleTrigger`.
L169: 
L170:      * The `frequency` element is set to `Minute` and the `interval` element is set to `15`. As such, the trigger runs the pipeline every 15 minutes between the start and end times.
L171: 
L172:      * The `timeZone` element specifies the time zone in which the trigger is created. This setting affects both `startTime` and `endTime`.
L173:      * The `endTime` element is one hour after the value of the `startTime` element. As such, the trigger runs the pipeline 15 minutes, 30 minutes, and 45 minutes after the start time. Don't forget to update the start time to the current UTC time and the end time to one hour past the start time.
L174: 
L175: Important
L176: 
L177: For the UTC time zone, `startTime` and `endTime` need to follow the format `yyyy-MM-ddTHH:mm:ss`Z. For other time zones, `startTime` and `endTime` follow the `yyyy-MM-ddTHH:mm:ss` format.
L178: Per the ISO 8601 standard, the `Z` suffix is used to timestamp mark the datetime to the UTC time zone and render the `timeZone` field useless. If the `Z` suffix for the UTC time zone is missing, the result is an error upon trigger activation.
L179: 
L180:      * The trigger is associated with the `Adfv2QuickStartPipeline` pipeline. To associate multiple pipelines with a trigger, add more `pipelineReference` sections.
L181:      * The pipeline in the quickstart takes two `parameters` values: `inputPath` and `outputPath`. You pass values for these parameters from the trigger.
L182: 
L183:   2. Create a trigger by using the cite35†Set-AzDataFactoryV2Trigger cmdlet:
L184: 
L185:     `Set-AzDataFactoryV2Trigger -ResourceGroupName $ResourceGroupName -DataFactoryName $DataFactoryName -Name "MyTrigger" -DefinitionFile "C:\ADFv2QuickStartPSH\MyTrigger.json"
L186:     `
L187:   3. Confirm that the status of the trigger is Stopped by using the cite36†Get-AzDataFactoryV2Trigger cmdlet:
L188: 
L189:     `Get-AzDataFactoryV2Trigger -ResourceGroupName $ResourceGroupName -DataFactoryName $DataFactoryName -Name "MyTrigger"
L190:     `
L191: 
L192:   4. Start the trigger by using the cite37†Start-AzDataFactoryV2Trigger cmdlet:
L193: 
L194:     `Start-AzDataFactoryV2Trigger -ResourceGroupName $ResourceGroupName -DataFactoryName $DataFactoryName -Name "MyTrigger"
L195:     `
L196:   5. Confirm that the status of the trigger is Started by using the cite36†Get-AzDataFactoryV2Trigger cmdlet:
L197: 
L198:     `Get-AzDataFactoryV2Trigger -ResourceGroupName $ResourceGroupName -DataFactoryName $DataFactoryName -Name "MyTrigger"
L199:     `
L200:   6. Get the trigger runs in Azure PowerShell by using the cite38†Get-AzDataFactoryV2TriggerRun cmdlet. To get the information about the trigger runs, execute the following command periodically. Update the `TriggerRunStartedAfter` and `TriggerRunStartedBefore` values to match the values in your trigger definition:
L201:     `Get-AzDataFactoryV2TriggerRun -ResourceGroupName $ResourceGroupName -DataFactoryName $DataFactoryName -TriggerName "MyTrigger" -TriggerRunStartedAfter "2017-12-08T00:00:00" -TriggerRunStartedBefore "2017-12-08T01:00:00"
L202:     `
L203: Note
L204: 
L205: The trigger time of schedule triggers are specified in the UTC timestamp. `TriggerRunStartedAfter` and `TriggerRunStartedBefore` also expect the UTC timestamp.
L206: 
L207: To monitor the trigger runs and pipeline runs in the Azure portal, see cite39†Monitor pipeline runs .

L379: Update the `start_time` variable to the current UTC time and the `end_time` variable to one hour past the current UTC time.
L380: 
L381:     `    # Create a trigger
L382:         tr_name = 'mytrigger'
L383:         scheduler_recurrence = ScheduleTriggerRecurrence(frequency='Minute', interval='15',start_time='2017-12-12T04:00:00Z', end_time='2017-12-12T05:00:00Z', time_zone='UTC')
L384:         pipeline_parameters = {'inputPath':'adftutorial/input', 'outputPath':'adftutorial/output'}
L385:         pipelines_to_run = []
L386:         pipeline_reference = PipelineReference('copyPipeline')
L387:         pipelines_to_run.append(TriggerPipelineReference(pipeline_reference, pipeline_parameters))
L388:         tr_properties = TriggerResource(properties=ScheduleTrigger(description='My scheduler trigger', pipelines = pipelines_to_run, recurrence=scheduler_recurrence))
L389:         adf_client.triggers.create_or_update(rg_name, df_name, tr_name, tr_properties)
L390: 
L391:         # Start the trigger
L392:         adf_client.triggers.start(rg_name, df_name, tr_name)
L393:     `
L394: To monitor the trigger runs and pipeline runs in the Azure portal, see cite39†Monitor pipeline runs .

L398: ## Pass the trigger start time to a pipeline
L399: Azure Data Factory version 1 supports reading or writing partitioned data by using the system variables `SliceStart`, `SliceEnd`, `WindowStart`, and `WindowEnd`. In the current version of Data Factory and Azure Synapse pipelines, you can achieve this behavior by using a pipeline parameter. The start time and scheduled time for the trigger are set as the value for the pipeline parameter.
L400: In the following example, the scheduled time for the trigger is passed as a value to the pipeline `scheduledRunTime` parameter:
L401: 
L402:     `"parameters": {
L403:         "scheduledRunTime": "@trigger().scheduledTime"
L404:     }
L405:     `

L454: ### Schema overview
L455: 
L456: The following table provides a high-level overview of the major schema elements that are related to recurrence and scheduling of a trigger.
L457: JSON property  | Description
L458: --- | ---
L459: `startTime`  | A Date-Time value. For simple schedules, the value of the `startTime` property applies to the first occurrence. For complex schedules, the trigger starts no sooner than the specified `startTime` value.
L460: For the UTC time zone, the format is `'yyyy-MM-ddTHH:mm:ssZ'`. For other time zones, the format is `yyyy-MM-ddTHH:mm:ss`.
L461: `endTime`  | The end date and time for the trigger. The trigger doesn't execute after the specified end date and time. The value for the property can't be in the past. This property is optional.
L462: For the UTC time zone, the format is `'yyyy-MM-ddTHH:mm:ssZ'`. For other time zones, the format is `yyyy-MM-ddTHH:mm:ss`.
L463: `timeZone`  | The time zone in which the trigger is created. This setting affects `startTime`, `endTime`, and `schedule`. See a cite57†list of supported time zones .
L464: `recurrence`  | A recurrence object that specifies the recurrence rules for the trigger. The recurrence object supports the `frequency`, `interval`, `endTime`, `count`, and `schedule` elements. When a recurrence object is defined, the `frequency` element is required. The other elements of the recurrence object are optional.
L465: `frequency`  | The unit of frequency at which the trigger recurs. The supported values include `minute,` `hour,` `day`, `week`, and `month`.
L466: `interval`  | A positive integer that denotes the interval for the `frequency` value, which determines how often the trigger runs. For example, if the `interval` is `3` and the `frequency` is `week`, the trigger recurs every 3 weeks.
L467: `schedule`  | The recurrence schedule for the trigger. A trigger with a specified `frequency` value alters its recurrence based on a recurrence schedule. The `schedule` property contains modifications for the recurrence that are based on minutes, hours, weekdays, month days, and week number.
L468: Important
L469: 
L470: For the UTC time zone, `startTime` and `endTime` need to follow the format `yyyy-MM-ddTHH:mm:ss`Z. For other time zones, `startTime` and `endTime` follow the `yyyy-MM-ddTHH:mm:ss` format.
L471: 
L472: Per the ISO 8601 standard, the Z suffix is used to timestamp mark the datetime to the UTC time zone and render the `timeZone` field useless. If the Z suffix is missing for the UTC time zone, the result is an error upon trigger activation.
