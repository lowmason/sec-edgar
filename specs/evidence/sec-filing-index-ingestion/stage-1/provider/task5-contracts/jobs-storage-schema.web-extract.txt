L24: # Containers in Azure Container Apps
L25: 
L26: Feedback
L27: 
L28: Summarize this article for me
L29: ## In this article
L30: 
L31: Azure Container Apps manages the details of Kubernetes and container orchestration for you. Containers in Azure Container Apps can use any runtime, programming language, or development stack of your choice.
L32: 
L33: cite5†Image: Azure Container Apps: Containers L34: 
L35: Azure Container Apps supports:
L36: 
L37:   * Any Linux-based x86-64 (`linux/amd64`) container image
L38:   * Containers from any public or private container registry
L39:   * Optional cite6†sidecar and cite7†init containers
L40: 
L41: Features also include:
L42:   * Apps use the `template` configuration section to define the container image and other settings. Changes to the `template` configuration section trigger a new cite8†container app revision .
L43:   * If a container crashes, it automatically restarts.
L44: 
L45: Jobs features include:
L46:   * Job executions use the `template` configuration section to define the container image and other settings when each execution starts.
L47:   * If a container exits with a non-zero exit code, the job execution is marked as failed. You can configure a job to retry failed executions.
L48: ## Configuration
L49: Most container apps have a single container. In advanced scenarios, an app can also have sidecar and init containers. In a container app definition, the main app and its sidecar containers are listed in the `containers` array in the cite9†`properties.template` section, and init containers are listed in the `initContainers` array. The following excerpt shows the available configuration options when setting up an app's containers.
L50: 
L51:     `{
L52:       "properties": {
L53:         "template": {
L54:           "containers": [
L55:             {
L56:               "name": "main",
L57:               "image": "[parameters('container_image')]",
L58:               "env": [
L59:                 {
L60:                   "name": "HTTP_PORT",
L61:                   "value": "80"
L62:                 },
L63:                 {
L64:                   "name": "SECRET_VAL",
L65:                   "secretRef": "mysecret"
L66:                 }
L67:               ],
L68:               "resources": {

L179: ## Multiple containers
L180: 
L181: In advanced scenarios, you can run multiple containers in a single container app. Use this pattern only in specific instances where your containers are tightly coupled.
L182: 
L183: For most microservice scenarios, the best practice is to deploy each service as a separate container app.
L184: 
L185: Multiple containers in the same container app share hard disk and network resources and experience the same cite8†application lifecycle .
